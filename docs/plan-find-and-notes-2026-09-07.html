Find, and two note instruments

Three things, one pass. A way to find a task or a sentence inside a note. A left-edge tape of the note’s sections, in the spirit of Grok’s chat ticks. Colour on a selected word, from the palette the app already has — no picker.

This is a plan, not a build. No code, no migration, no ADR file until the owner says go. The decisions below are locked so the build does not invent. Say if D2 or D5 is wrong; the rest follows from the product as it stands.

01 Three verbs, already almost there

The shell already has Capture (⌘J, filled pill) and Ask (the outlined pill to /chat). Find is the missing third verb. It does not get a pill. DESIGN.md spent the two standing actions on purpose; a third one would make Capture ordinary.

Capture · ⌘J
A thought in. The plus. Persist first, parse second. Already the product.
Find · ⌘K
A thing that already exists. Tasks and notes. This plan.
Ask · /chat
A question over a snapshot. Read-only. Stays that. Find locates; Ask talks.
Why Find is not Chat. Chat answers “what did I say about the dentist.” Find answers “where is the dentist.” Mixing them makes both worse: a locate tool that writes prose, and a reader that you have to wait on to open a row. The owner already has both jobs. They get two doors.

02 Find

A command palette over the two piles you actually lose things in. The link picker already searches task titles with ilike. This is that idea, grown up: titles and bodies, tasks and notes, one box, ranked.

The scene

At the keyboard. You remember a word, not a route. You press ⌘K. You type dentista. Two groups appear: Tasks, then Notes. A title match sits above a body match. A body match shows a one-line snippet with the word marked. Enter opens the row — /tasks?edit= or /notes/[id]. Escape closes. The composer never creates anything.

On a phone there is no ⌘K. Find sits in the More menu, Daily section, next to Ask. Same palette, same action, opened from the menu instead of a key.

What “smart” is, and what it is not

The gap today is that nothing reads notes.body or tasks.notes. The link picker looks at task titles. Chat looks at a capped snapshot and then talks. Neither is Find.

Smart, here, is ranking and a snippet:

  • A title hit outranks a body hit. Always. You named it; that is the thing.
  • Inside a group, open tasks sit above done; needs_review notes sit above the rest. Then recency.
  • A body hit carries ~80 characters around the first match, markdown stripped, the query marked in accent-ink. The stored body is never mutated.
  • Quiet tasks still appear. Find is not Today. Parking a project must not hide the row from a search for its words.
  • Two characters minimum. Empty query shows recents: five open tasks, five recent notes. A blank box is a dead control.
  • Cap eight per group. A palette is not a search-engine page.

Not smart: embeddings, a second model, typo-tolerant trigrams, “search everything.” pg_trgm is a later index if ILIKE ever feels slow, which a single-user corpus will not. Journal, quotes, people, links, events, the notification ledger — named as a growth path, not built. Searching “Ana” already hits a task whose title or notes contain Ana; mentions do not need a second index.

How it is built

One server action behind requireOwner(). One service, lib/services/find.ts, that queries tasks and notes in parallel with the same escaped ilike the link picker already uses. Ranking is applied in process on the small cap, not in SQL. No generated tsvector column. No migration. Bilingual content is stored verbatim; ilike is case-insensitive and language-agnostic, which is the honest choice for mixed PT-BR/EN. An English FTS config would stem the wrong language.

The palette is a sibling of CapturePalette: a bus, a shortcut helper, a Dialog, mounted once in the authed shell. ⌘J stays Capture. ⌘K is Find. They must not steal each other’s key. Debounce 150ms on the client so a fast typist does not fire six round-trips.

03 The section tape

Grok puts a column of little lines on the right of a chat, one per turn. A note is not a chat, and the right side of this page is already the links rail (ADR-0047). The tape goes on the left. It is a scroll widget, not a table of contents.

The argument

A long note is a document you are inside. Headings already exist — the closed ramp, # / ## / ###. What is missing is a way to see the shape without scrolling it. Equal-height ticks would be a TOC. Proportional ticks are a map: a long section is a long mark, a short one is a nick, and the mark that is “now” is ink. Click a mark, the heading comes to you.

The title of the note is the first mark. Headings in the body are the rest. Depth is encoded as inset, not as a second colour: h1 reaches the left edge, h2 steps in, h3 steps in again. Colour is reserved for “you are here.” Accent is not used — accent means overdue, and a heading is not overdue.

When it appears

  • Hidden when the note has fewer than two marks (title plus one heading). A tape of one is a decoration.
  • Hidden when the whole note fits in the viewport. A map of a room you can already see is noise.
  • On a phone, it becomes a 6px overlay on the left edge of the editor, not a grid column. It must not steal the 65ch. Tap still jumps. Hover labels do not exist on a phone; the jump is the feedback.
  • Hover/focus on desk names the heading in a native title and an accessible name. The ticks themselves stay unlabeled. Grok’s lines are unlabeled too — the point is the shape, not another outline.

How it is built

A client companion of NoteEditor, reading the TipTap doc on update: the title input plus every heading node, with its position in the document and its depth. Positions map onto the tape’s height as a fraction of the article’s rendered height, so a section that is half the note is half the tape. Scroll-spy against #main (the shell is the scroller, ADR-0028) marks the current section. Click calls scrollIntoView on that heading. prefers-reduced-motion jumps, it does not smooth-scroll.

No new primitive. No PageHeader. The breadcrumb stays the locator. The tape is not a nav landmark; it is aria-label="Note sections" on a list of links, and it is omitted from the tab order’s long way through — ticks are pointing devices first, keyboard gets the headings in the body.

04 Colour on a word

Select a word, apply one of the colours the app already speaks. No picker, no hex, no highlight-marker. The stored value is a palette slug so light and dark both resolve it, the same way a domain dot already does.

The set

Domains already have nine slugs in lib/schemas/color.ts. Body text is not a 9px dot, so the Travel exemption that lets yellow be a full yellow (1.45:1 on light ground) cannot come along. Accent cannot come along either: it is the overdue/interactive state, and a coloured word must not look like a control. That leaves eight.

Indigo · engine Green · health Orchid · family Clay · spirit Blue · finance Cyan · code Teal · pine Rose · burgundy Yellow · travel

A coloured word is not a domain tag. Colouring a sentence green does not file the note under Health. Filing stays the ScopeSelect under the editor. The slug is reused because it is the closed set the owner already knows from the domain picker, and because ColorSwatchPicker already renders it.

Storage, and why markdown stays

ADR-0009 stores the body as markdown text, serialized by tiptap-markdown with html: false. That rule stands. Colour is one inline mark with a slug attribute. On the way out it writes:

<span data-ink="health">dentista</span>

On the way in, only a span[data-ink] whose value is one of the eight slugs becomes a mark. Any other HTML stays text. Unknown slugs strip to plain. Hex, style=, <font> — gone. Capture can still dump a raw angle bracket into a note and it will show as a bracket, not as markup.

This is the same escape hatch empty paragraphs already use (&nbsp; in, empty <p> out). We are not turning the editor into an HTML store. We are naming one tag the serializer may emit, and we are writing that down in an amendment to ADR-0009 so the next reader does not treat it as drift.

The bubble

The editor has no toolbar today. Markdown shortcuts own bold, italic, lists, headings. That does not change. Colour has no markdown shortcut worth teaching, so it appears only when the selection is non-empty: a TipTap BubbleMenu of eight swatches plus clear. Reuse the swatch language from ColorSwatchPicker — same size, same ring, same labels — in a compact row. Applying a colour to a selection that already has one replaces it. Clear removes the mark and the word returns to ink.

iOS selection handles and the bubble will fight; that is a known TipTap tax. The bubble must sit above the selection, not over the native handles, and it must not steal the first tap. If that cannot be made decent on a phone, colour is a desk feature and the bubble does not mount below lg. That fallback is allowed. Inventing a second colour UI for the phone is not.

07 Constraints the build may not invent past

Still true

  • Iron rules 1–6. Find is a read, so #6 does not fire. Colour is user-authored, so #5 (verbatim) still holds — we store the words, plus a slug.
  • requireOwner() on the Find action. No /api/find.
  • Services take sb first.
  • UI chrome English. Content in the language it was written.
  • Semantic tokens only. No raw hex in components.
  • The two standing header actions stay two.

Load-bearing files

  • lib/services/tasks.ts — searchTasksByTitle is the ancestor, not the implementation. Leave it; the link picker still needs a title-only search.
  • app/(authed)/notes/[id]/note-editor.tsx — html: false stays. The mark’s own serializer is the hatch.
  • lib/schemas/color.ts — do not add a tenth slug. Subtract travel at the ink layer.
  • components/color-swatch-picker.tsx — visual language to copy, not a component to reuse on a bubble (it is a form fieldset).
  • #main is the scroller. The tape spies on that, not window.

08 Two things to confirm

Everything else is locked. These two change the build if you disagree. The recommendation is the locked value in the table above.

O1Is v1 really only tasks and notes?

Journal, quotes, people and links are all findable in principle. Adding them is a group in the palette and a query in the service. The cost is a fatter empty-recents state and a ranking that has to mean something across four kinds.

Recommend: tasks + notes only. You lose things in those two. Quotes you reread from Today. People you open from a mention. Grow the corpus after you have used Find for a week.

O2Colour on a phone — ship it, or desk-only?

iOS selection handles and a bubble menu share one thumb. If the first tap dismisses the native selection, colour becomes a fight, not a feature. Desk is the design-leading scene (PRODUCT.md).

Recommend: build the bubble for desk. If the phone pass is decent, keep it. If it is not, do not mount below lg and do not invent a second UI. Colour remains in the stored markdown either way, so a phone still renders it.
