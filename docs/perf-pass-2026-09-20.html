The performance pass

The app was slow to open and worse to come back to. This is what was wrong, what changed, and what was left alone on purpose. The decisions themselves live in ADR-0062; this page is the readable version.

What was actually wrong

Three causes, found by measuring rather than guessing. The first one was most of the problem.

1. The server was on the wrong continent

Functions were built for iad1 (Virginia). Supabase is in sa-east-1 (São Paulo), and the only person using the app is in Brazil. So every page was: browser → São Paulo edge → Virginia → back to São Paulo for the data → and back again. Today makes two or three waves of queries. That is most of a second spent purely travelling, before any work happens.

2. The cache died after ten minutes

Cached reads expired after 600–900 seconds. But every write in the app already clears the cache by tag, so the clock was not keeping anything honest — it only guaranteed that coming back after ten minutes away paid the whole database fan-out again, behind a skeleton. This is exactly the "away for a while and it's slow" symptom.

3. Nothing could paint until a cookie was read

The prerendered page of every screen was literally the word "Loading". The shell waited on an auth check, so the header, the dock, the page frame and the palettes were all trapped behind one server call on another continent. Partial Prerendering had nothing to serve.

What changed

01 The server moved to São Paulo

vercel.json · commit 2e4d7cf

regions: ["gru1"]. The server now sits next to the database and next to you. This is a latency decision, not a preference — the region has to follow wherever Supabase lives.

Also trimmed the auth proxy so /sw.js and /manifest.webmanifest stop paying a full auth check on every service-worker poll and every app launch. A cold PWA was being redirected to the sign-in page for its manifest file.

Database round trip: ~230ms → ~5ms. Verified live: every function reads [gru1].

02 Cached reads live a week, not ten minutes

next.config.ts, lib/cache/* · commit 538fb65

One shared profile replaces five hand-written ones: stale 5 minutes, refresh after 1 hour, expire after 7 days. The hour is the part that matters — past it, the app serves what it has immediately and refreshes behind the response. Nobody waits.

This is only safe because tags, not time, keep the cache honest. Which made one real bug visible and worth fixing: resolving a note in the app did not clear Today's "needs review" counter. Harmless at ten minutes; not at seven days.

Three query fixes rode along: a needless extra round trip on Today's critical path, full note bodies being shipped to the browser for every note-page open, and a select("*") on the people page.

03 The app frame paints from the CDN

app/(authed)/layout.tsx · commits ea158bf, 3351afe

The auth check moved out of the shell and into a component that renders nothing, inside its own boundary. Now the nav, the dock and the page frame are prerendered and served from the edge; only the data waits on the server.

Nothing got less secure. The frame is the same markup on every screen and carries no data, the proxy still turns away anyone not signed in, and every page still checks ownership before reading anything. An independent reviewer confirmed this before the merge.

This broke something, and the fix is worth knowing about. The Capture button is placed into the dock by a portal. Once the dock was inside a loading boundary, the page froze on its skeleton forever — a hydration failure that looks exactly like a slow server. The slot now lives outside the boundary.

Shells went from “Dispatch Loading” to the full frame, 12K, from the CDN.

04 Tabs prefetch when you reach for them

components/intent-link.tsx · commit a3a66d7

Borrowed from t3code's defaultPreload: "intent". Pointing at a tab — hover, first touch, or keyboard focus — fetches that screen's data a moment before you click it.

The obvious alternative, prefetching all five tabs on page load, would fire five full page renders every time you open the app. On a phone that is the worst possible moment for it.

React Compiler is also on now, which memoizes the big interactive lists automatically. Checked in the build output rather than assumed: 133 generated memo sites.

05 The date pickers load when you open the form

app/(authed)/tasks/task-fields.tsx · commit 1829384

The date and time pickers are the heaviest thing in the app — about 435 KB — and the only place they appear is inside the task form. They were being downloaded on every single visit to Tasks, for a form most visits never open. Now they arrive when the form does.

/tasks JavaScript: 1685 KB → 1310 KB.

Left alone on purpose

Each of these was considered and rejected with a reason, recorded so a future pass does not spend the same hours re-deciding them.

Luxon stays in the browser bundle (72 KB)

Removing it means splitting lib/dates.ts, which iron rule #1 makes the single home of date logic. The functions the browser actually calls take Luxon format strings. Reimplementing a date-format parser to save 4% is how dates start disagreeing with themselves.

The note editor still loads up front

Deferring the editor on the page whose entire purpose is the editor only adds a wait before you can type.

The session keeper still loads Supabase eagerly (220 KB)

Delaying it would delay the token refresh, and ADR-0025 and ADR-0032 are emphatic that the browser must refresh ahead of the request fan-out. That bug — the PWA bouncing you to sign-in — cost more than 220 KB is worth.

Today's 5-minute auto-refresh still clears the whole client cache

Rewiring it risks the day-navigation logic ADR-0034 carefully pinned down, and the same refresh also updates the counters, the badge and the midnight rollover — a naive swap fixes the day bands and quietly stops updating all of that. This one was judged, not measured. There is a handoff document for it if you want it revisited; measure first.

Still yours to check

Two behaviour checks were never run, because they write to real data and that is not mine to touch. Tick a task on Today and confirm the counter moves and stays moved. Resolve a note that needs review and confirm Today's needs-review count drops — that second one exercises the cache-tag bug fixed in 538fb65.
Seven commits on main, 2e4d7cf through dff44c0. Reviewed before merge by an independent checker on a different model family, which found one real issue (a prefetch handler that could silently switch itself off) — fixed in dff44c0. Decisions: ADR-0062.
