Edges — what the app says when something is wrong

Pass 5 Phase 0 gate. The app has three different moments at the edge of a surface, and only one of them has ever been designed:

Waiting

Data in flight. PageSkeleton is the system answer. EditorFallback + LinkSectionsFallback are the only two that were never asked.

Absent

Nothing here yet. EmptyState — left-aligned italic ink-3, upright hint beneath. Settled in Pass 0.

Broken / missing

Something failed, or the address is wrong. error · authed 404 · root 404 · toast — migrated, never designed.

The gate is the register for broken/missing, and how far it may sit from absent. Waiting is drawn with every package because the brief requires the two note fallbacks to be asked — they may keep their own shape; what they must not keep is being unconsidered.

The axis (broken vs absent)

How far is failure allowed to sit from EmptyState? Type weight, PageHeader yes/no, toast elevation, and whether recovery is a primary button all move with that distance. Waiting is not on this axis — it is a third state drawn beside it.

As shipped — they do not agree

Not an option. Every edge surface as it lives in the tree today, so the disagreement is visible before the packages. Desk and phone under the width toggle.

Waiting — the system answer and the exception

Route-level loading goes through PageSkeleton: real PageHeader, no measure (counts would lie), body as pulse rows. The note editor declined PageHeader in Pass 3, so its Suspense boundaries hand-rolled content-shaped pulses — EditorFallback (title + prose bars on the measure) and LinkSectionsFallback (section heads + rows in the rail).

They are waiting, not failing. The question is only whether that shape is still right once failure and absence have a register — keep the content-shaped pulse (record why), or converge on something the packages below also own.

A Near — same register as EmptyState

A failure is not a special page. It is a moment the content is unavailable. Borrow EmptyState's quiet italic lead and upright next step; do not promote the moment to headline weight.

Wins: one voice for "nothing useful here." The italic is already the app speaking. Recovery is an instruction, not a ceremony.
Costs: a crashed route looks like an empty list. On a full page that can under-announce a real problem.
Waiting under A: keep content-shaped pulses — waiting is not empty copy, and A does not invent a loading sentence. The fallbacks stay shape, with a recorded reason.

broken: no PageHeader · 16 italic ink-3 · 14 roman ink-4 hint · quiet action · toast flat/italic · root: brand + same quiet block
absent: EmptyState unchanged
waiting: EditorFallback + LinkSectionsFallback keep pulse geometry

B Page — failure owns the route leans

When the route failed, the page is the failure. Name it at PageHeader weight — the fine locator still works when the body has nothing to show — and keep EmptyState as the in-list quiet form. Distance is structural: page vs slot, not louder type.

Wins: matches every other authed surface. Root 404 drops the legacy silhouette. Toast is a compact card in the same operational English. Empty stays lighter because it never takes the h1.
Costs: a missing note still gets a 36px title. Wry copy ("sideways") dies — the header will not oversell a shrug.
Waiting under B: PageSkeleton remains the route-level answer. Note fallbacks keep content-shaped pulses because the note has no PageHeader to hold — same call Pass 3 made, now explicit.

broken: PageHeader 36/30 · roman body · primary recovery on error · mono nav on 404 · root: brand + h1, no eyebrow/hairline · toast: surface card, medium title, error border · plain operational English
absent: EmptyState unchanged
waiting: PageSkeleton on routes · note pulses keep shape

C Signal — broken is not empty

Conflating broken with empty trains the reader to ignore both. Failure keeps page weight and adds one deliberate signal the empty register never gets: a thin error-ink rule on the recovery block for fault only. Missing (404) stays at page weight without the colour. Absence stays the quiet italic. Waiting never takes the signal.

Wins: three-way split is visible without a banner. Toast and route error share recovery grammar. EmptyState is protected.
Costs: spends error colour on chrome the app almost never uses. Risks "alert UI." Not-found is not a crash — the signal must not fire there.
Waiting under C: same as B. Pulse bars stay uncoloured; a loading state with an error rule would be a lie.

broken (fault): PageHeader · 2px error rule on recovery · primary ink button · toast error border
broken (missing): PageHeader · quiet nav · no error rule
absent / waiting: EmptyState and pulses untouched by error colour
