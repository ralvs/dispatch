Fork A — when is More lit?

You are on Projects. The menu is closed. Which dock tab shows the active mark?

Today’s behaviour (when More was a page): More stays lit for every destination it hosts, so the bar always answers “where am I?”. That rule can survive the menu, or die with the page.

A1Lit while you are in a hosted destination

Projects / Settings / Domains / … all light More in the dock, even with the menu closed. The dock still says “you are in the overflow set.” Same as today’s alias behaviour.

Cost: More looks like a place you are “on”, even though it is only a menu. The active mark no longer means “this tab’s page.”

A2Lit only while the menu is open

On Projects with the menu closed, no tab is lit — none of Today / Tasks / Notes / Links owns the route, and More is chrome not a destination. More lights only for the moment the sheet is open.

Cost: standing on Projects, the dock has no active mark. Wayfinding is the page title alone. Cleaner contract (“active = this surface”), emptier dock.

Fork B — how does desk open More?

There is no rail. Desk reaches Library and System only through the header. Both options keep the five-tab header; they differ only in how the menu attaches when you press More.

(An earlier note about “drop More and use the rail” was wrong for this shell — the rail is already gone. That option is not on the ballot.)

B1Popover under the tab group

More is a tab. Press it → a compact menu floats under the tab group. Same inventory as the phone sheet. Page behind stays put.

Cost: a floating panel on desktop. Familiar pattern; one more layer to dismiss.

B2Panel under the whole header

More is a tab. Press it → a full-width panel drops under the header (three columns: Daily / Library / System). More room, reads closer to a command strip than a menu.

Cost: heavier chrome; pushes page content down while open. Worth it only if nine destinations feel cramped in a 260px popover.

2 · Fork B — B1 (popover) or B2 (full-width panel)? Phone sheet is already settled.
