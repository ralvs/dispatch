Gate A — what weight is a name?

Pass 1 dropped the task title to 400, with P1 the single step to 500: “It was 500 on every row, which spends the system’s only weight step equally everywhere and so says nothing.” Every other row is still 500 via .type-title. Either the argument generalises, or /tasks is the exception and that exception gets stated as a rule.

A1Rest — every name is 400 recommend

The Two Weights Rule generalises. Hierarchy on a list comes from colour, position, and the mono meta — not from weight. .type-title loses most of its ~24 call sites; the 500 step is reserved for the one thing that still earns it (P1 on a task, a section head, a page name).

Cost: a project name and a person name no longer shout relative to their own meta. If the list feels flat, the flatness is honest — there is no priority on these objects to spend the step on.

name 16 / 400 / −0.01em · domain dot left, holds when absent · SectionHead 16 / 500 · furniture held constant (B1) so weight is the only variable

A2Exception — object names stay 500

/tasks is the one list with a priority worth spending the step on. Everything else keeps 500 because a name is a name, and a row of names is what these pages are. The exception is written as a rule: task titles are 400; object titles are 500.

Cost: two weights for one kind of thing (a 16px row name) live in the same visual language, two rows apart when Today and Projects share a screen in memory. The rule has to be remembered; it cannot be read off the page.

name 16 / 500 / −0.01em · same geometry as A1 · same furniture · the difference is only the weight

Gate B — do the inline forms follow ADR-0043?

Five surfaces open with a CollapsibleForm above the list: /projects, /people, /quotes, /routines, /journal. ADR-0043 deleted exactly this shape from /tasks and moved the write behind one control on the title. /projects is already recorded as this pass’s job (it gains a create action in the slot /notes already uses). What is not decided is the rule the other four fall under — and whether /journal is the same kind of thing.

Weight held at A1 (400) so furniture is the only variable. Look at how much list you can see before the fold, and whether a create action competes with the shell’s Capture pill.

B1Write behind the header recommend

Rule: a list of objects opens as a list. Creating an object is one action on the page’s name (or its right edge), never standing furniture above the first row. The form becomes a dialog — same move ADR-0043 made, and the one the Pass 0 comps already recorded for /projects.

Applies to: /projects, /people, /quotes, /routines — each creates an object beside a list of the same objects. Control voice: labelled + New … in the action slot, matching /notes. The bare title-shoulder + stays /tasks’s, where a second labelled create next to Capture was the confusion ADR-0043 removed.

no CollapsibleForm on the page · action mono control, “+ New project / person” · form is a dialog (not drawn — the absence is the point) · weight 400

B2Standing form stays

Rule: ADR-0043 was local to /tasks because that page already had Capture and a second write path. Object lists keep the collapsible create card — it is how these pages have always written, and the fields are few enough that an inline form is not a second Capture.

Cost: two shapes for one kind of action ship in the same app: dialog behind + on Tasks/Notes/Projects (if Projects still moves), and a card that opens in place on People/Quotes/Routines. The list’s first rows start ~180px lower whenever the form is open — which, on create-heavy days, is most of the time you are on the page.

CollapsibleForm open (the expensive state) · no header action · weight 400 · /projects drawn the same way for the comparison, even though Pass 0 already recorded it moving

Where /journal falls

Under B1’s rule, journal is the exception that proves it: writing the entry is the page, not a create action beside a list of entries. Standing furniture is correct there for the same reason the capture line was wrong on /tasks. Pass 3 applies this; this gate only settles that journal is not an object-list.

Under B2’s rule, journal needs no special pleading — it already matches the other four. The cost is that the rule cannot later explain why Tasks and Notes write one way and the rest another.

What to look for

1 · A1 vs A2 on /people — the simplest row. If you cannot feel the weight step without the chip under the frame, A2 is spending a signal nobody will read.

2 · A1 vs the Tasks reference — at 400, a project name and a P4 task title are the same weight. That is either the system becoming one language, or the task list losing its only hierarchy tool. P1 still steps to 500 either way.

3 · B2 open on phone — the form eats the first screen. Count how many rows you can see before scrolling. That is the cost of standing furniture.

4 · B1 against Capture — on desktop the shell’s Capture pill sits top-right. A labelled + New project is the notes pattern and lives under More, so it does not compete the way a second + New task did. If it still reads as a second Capture to you, the bare title-shoulder + is the escape hatch — say so.

5 · Two dots, gone — every project row carries one domain dot on the left, not a project colour before the name and a domain colour in the meta. That is not on the ballot; it is the encoding Pass 1 already settled.
